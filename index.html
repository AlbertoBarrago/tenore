Work in progress · v0.2

One source.
Every agent.

tenore compiles a single .agents/ folder (Markdown + YAML) into the native instructions, permissions, MCP servers and memory of each AI coding agent. Switching agent becomes a 1:1 port.

Get started

npm install -g tenore-cli
cd your-project
tenore init            # guided setup for this repository
tenore init --global   # guided setup for your personal config

The wizard finds your existing agent config, imports what you pick into .agents/, asks which agents to generate files for, previews the sync and runs it. Nothing is written until you confirm, and it ends with the equivalent commands so you can script the same setup.

The problem

Claude Code, Codex CLI and Antigravity each have their own format for the same ideas. You write your rules three times, they drift apart, and a permission tightened in one tool stays wide open in another.

How it works

.agents/
  AGENTS.md      # instructions
  policy.md      # permissions, mcp
  memory/*.md    # one topic per file
  local/         # gitignored
→
Claude Code
CLAUDE.md · settings.json · .mcp.jsondone
Codex CLI
AGENTS.md · config.toml · .rulesdone
Antigravity
.agents/ rules · settings.json · mcp_config.jsondone

Three scopes merge deterministically: ~/.agents (global), <repo>/.agents, and .agents/local. Lists concatenate, narrower scalars win, and deny always wins. Pick the agents you use with targets: [claude, codex], or all of them by default.

Write it once

.agents/policy.md

---
targets: [claude, codex, antigravity]
permissions:
  default: ask
  allow:
    - shell: "npm run test*"
    - fs.write: "src/**"
  ask:
    - shell: "git push *"
  deny:
    - fs.read: ".env*"
    - network: none
mcp:
  github:
    command: npx
    args: [-y, "@mcp/github"]
    env:
      GITHUB_TOKEN: "${env:GITHUB_TOKEN}"
overrides:
  codex: { permission_profiles: true }
---

.claude/settings.json (owned keys only)

{
  "permissions": {
    "allow": [
      "Bash(npm run test*)",
      "Edit(/src/**)"
    ],
    "ask": ["Bash(git push *)"],
    "deny": [
      "Read(.env*)",
      "WebFetch",
      "WebSearch"
    ],
    "defaultMode": "default"
  }
}

.mcp.json

"env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }

.codex/rules/tenore.rules

prefix_rule(pattern = ["git", "push"], decision = "prompt")

.codex/config.toml (owned keys only)

approval_policy = "on-request"
web_search = "disabled"
default_permissions = "tenore"

[mcp_servers.github]
command = "npx"
args = [ "-y", "@mcp/github" ]
env_vars = [ "GITHUB_TOKEN" ]

[permissions.tenore.filesystem.":workspace_roots"]
"**/.env*" = "deny"
"src/**" = "write"

[permissions.tenore.network]
enabled = false

~/.gemini/antigravity-cli/settings.json (owned keys only)

{
  "permissions": {
    "allow": [
      "command(regex:npm run test.*)",
      "write_file(src/)"
    ],
    "ask": ["command(git push)"],
    "deny": ["read_url(*)", "execute_url(*)"]
  },
  "toolPermission": "request-review"
}

.agents/mcp_config.json

"github": {
  "command": "npx",
  "args": ["-y", "@mcp/github"]
}

GITHUB_TOKEN is inherited from agy's environment, never written.

Real output of tenore sync. What a target cannot express (here: .env* globs in Antigravity, which only takes paths) is reported as a warning instead of being silently widened.

Safe by construction

Never widens permissions

If a target cannot express a rule exactly, tenore picks the more restrictive option and tells you.

Secrets stay references

${env:VAR} is translated, never resolved into a generated file.

Drift detection

Generated files are hashed in .agents/.lock. Hand edits are reported, never overwritten.

Round-trip import

Import your existing CLAUDE.md and settings, sync, import again: same model.

Surgical merges

Shared JSON files are merged on owned keys only. Everything else you configured is left alone.

Atomic writes

Temp file plus rename. A crashed sync never leaves a half-written config.

Checked against the real CLIs

Codex rules and sandbox profiles are tested with codex execpolicy and codex sandbox; MCP env handling was probed on agy.

No code in config

Executable frontmatter (---js) is refused: a cloned repo cannot run code through tenore.

Guided, never surprising

The setup wizard writes nothing until you confirm, and shows the full diff before touching your personal config.

CI ready

tenore check exits 1 on drift, conflicts, schema errors or pending changes.

CLI

CommandWhat it does
tenore initSetup wizard: import existing config, pick target agents, preview and sync. Prints the equivalent commands
tenore init --import claude|codex|antigravityPull an agent's existing config into .agents/
tenore init --targets claude,codexChoose which agents get generated files
tenore sync [--prune]Compile .agents/ into every target's native files; --prune removes files of dropped targets
tenore diffDry-run sync, unified diff output
tenore mcpShared memory as MCP tools (list, read, search, write) for every agent
tenore checkExit 1 on drift, conflicts, schema errors or pending changes, for CI
--global, --targetInclude ~/.agents; override the policy's targets
